工具设计速查

Agent Tool 的定义规范、错误处理模式与注册表架构。

Tool Schema 模板

{
  type: 'function',
  name: 'verb_noun',           // 小写_下划线，动词开头
  description: [
    '做什么。何时用。返回什么。',
    '边界：什么情况不该用。'
  ].join(' '),
  parameters: {
    type: 'object',
    properties: {
      required_param: { type: 'string', description: '...' },
      optional_param: { type: 'string', description: '...' },
    },
    required: ['required_param'],
    additionalProperties: false,  // 必须
  },
  strict: true,                   // 必须
}

命名规范

领域模式示例
CRUD{add|get|list|update|delete}_{resource}add_todo, list_todos
查询{search|find|query}_{target}search_contacts
多域命名空间{domain}_{action}_{resource}todo_add, file_read

Description 清单

一条好的 description 回答四个问题：

  1. 做什么：一句话功能概述
  2. 何时用：与相似工具的区分
  3. 返回什么：输出内容的简要说明
  4. 边界：不能做的事，不该用的场景

错误处理模式

原则做法
不抛异常工具 handler 用 try/catch 包裹，返回错误文本
说明原因"文件不存在" 而非 "ENOENT"
给建议"请先用 create_file 创建该文件"
可操作让模型知道下一步怎么做
 
// ✅ 模型能理解并修正
return "错误：未找到名为 'work' 的标签。可用标签：personal, urgent, later。";

// ❌ 模型不知所措
throw new Error("INVALID_TAG");

工具注册表架构

// registry.ts
const tools = new Map<string, { schema: Tool; handler: Fn }>();

registerTool(name, schema, handler)  // 注册
getToolSchemas(): Tool[]              // 给 Agent Loop 用
executeTool(call): Promise<string>    // 路由 + 错误包裹

Agent Loop 只依赖 getToolSchemas() 和 executeTool()，不感知具体实现。
