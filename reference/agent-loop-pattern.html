Agent Loop 速查

Responses API 下的 Agent Loop 标准模式。本仓库所有 Agent 实现以此为基。

伪代码骨架

function runAgent(client, initialInput, tools, options):
    currentInput = [...initialInput]
    trajectory = []
    steps = 0

    while steps < options.maxSteps:
        response = call_model(client, currentInput, tools, options)
        trajectory.push({ step: steps, output: response.output })
        currentInput.push(...response.output)

        function_calls = filter(response.output, type == 'function_call')
        if function_calls.length == 0:
            break   // 没有 tool call → 任务完成

        outputs = []
        for each call in function_calls:
            result = execute_tool(call.name, call.arguments)
            outputs.push({
                type: 'function_call_output',
                call_id: call.call_id,
                output: result
            })

        currentInput.push(...outputs)
        steps++

    return { output: currentInput, trajectory, steps }

关键参数

参数 含义 建议默认值
maxSteps 模型→工具→模型 循环的最大次数 10（简单任务），可按场景调
tools 模型可用的工具列表（OpenAI.Responses.Tool[]） 从工具注册表传入
instructions 系统级行为约束（角色、边界、格式要求） 至少一句话，不能为空

终止条件（本仓库标准）

条件 何时触发 行为
自然完成 模型返回的 output 中无 function_call 返回 output_text / message 给用户
步数上限 steps >= maxSteps 返回当前结果 + 告知未完成
工具失败（后续） 工具抛异常且无法 fallback 记录错误到轨迹，优雅退出

Input 拼接规则

在 Responses API 中，input 是一个 ResponseInputItem[] 列表。拼接顺序：

  1. 初始 user message
  2. 模型第 1 轮 output（包含 function_call 和 message）
  3. application 回写的 function_call_output
  4. 模型第 2 轮 output ……
  5. ……循环
// 每一步的正确操作：
currentInput.push(...response.output);   // 先压模型输出
// 执行工具后：
currentInput.push(...functionCallOutputs);  // 再压工具结果
// 下一轮调用时 currentInput 包含了完整历史

轨迹最小字段

字段 来源
step当前步数（从 0 起）
modelOutputresponse.output 完整记录
toolCalls从 output 中过滤出的 function_call items
toolResults你写回的 function_call_output items
