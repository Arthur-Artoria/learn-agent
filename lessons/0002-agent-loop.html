Agent Loop：从单轮 Tool 到 runAgent

你已经会了 tool calling 的「一步」。Agent 的分水岭是把这一步包进循环——让模型在需要时多次调用工具， 直到任务完成或被限制打断。

约 10–15 分钟 前置：L0–L3（已掌握） 术语表 Agent Loop 速查

1. 你差的那一步

对比你仓库里两个函数的区别——这是本课唯一需要「看懂」的核心：

你现在有的 
// L3: getHoroscopeFunctionCalling
1. 带 tools 调模型
2. 从 output 取 function_call
3. 执行 getHoroscope
4. 把 function_call_output 塞回 input
5. 再调一次模型 → 答案
// 只跑一轮，硬编码两次调用
你要变成的 
// L5: Agent Loop
1. 调模型（带 tools）
2. while (有 function_call && steps < maxSteps) {
     执行所有工具
     回填 function_call_output
     再调模型
   }
3. 返回最终 output_text
// 循环直到没有 tool call 或触上限
Anthropic 的简洁定义： "Agents are just LLMs using tools based on environmental feedback in a loop."
— Building effective agents

2. Agent Loop 的解剖

下面是在本仓库中即将落到 src/agent/loop.ts 的核心结构：

// agent/loop.ts 的核心骨架
async function runAgent(client, input, tools, options) {
  let currentInput = [...input];
  const trajectory = [];  // 记录每一步，debug 用
  let steps = 0;

  while (steps < options.maxSteps) {
    // ① 调模型
    const response = await client.responses.create({
      model: options.model,
      input: currentInput,
      tools,
      instructions: options.instructions,
    });

    trajectory.push({ step: steps, output: response.output });
    currentInput.push(...response.output);

    // ② 收集本轮的 function_call
    const functionCalls = response.output.filter(
      item => item.type === 'function_call'
    );

    // ③ 没有 tool call → 任务结束
    if (functionCalls.length === 0) break;

    // ④ 依次执行工具
    const outputs = [];
    for (const call of functionCalls) {
      const result = await executeTool(call);
      outputs.push({
        type: 'function_call_output',
        call_id: call.call_id,
        output: result,
      });
    }

    // ⑤ 回填 tool results
    currentInput.push(...outputs);
    steps++;
  }

  return { finalOutput: currentInput, trajectory, steps };
}

3. 从你现有代码到 Agent Loop 的映射

打开你的 FunctionCalling.ts，只看 getHoroscopeFunctionCalling。 它已经包含了 loop 所需的所有原子操作，只是被「展开」（unrolled）了一轮：

现有代码行 做了什么 在 loop 中变成
client.responses.create({ input, tools }) 调模型 循环体第 ① 步，每次都用最新的 currentInput
response.output.filter(...function_call) 提取 tool call 循环体第 ② 步，每轮都可能不同
getHoroscope(JSON.parse(...)) 执行工具 循环体第 ④ 步，按 name 路由到具体实现
input.push(...functionCallOutput) 回填结果 循环体第 ⑤ 步，然后回到 while 判断
（不存在） 循环条件判断 while 头 + break 条件

关键认知：你不需要学新 API，只需要给你已会的代码加一层 while + 计数 + break。

4. 什么时候结束？三种终止条件

条件 A

没有 function_call 了

模型本轮输出里只剩纯文本（output_text 或 message）——任务已完成，自然终止。

条件 B

达到 maxSteps

步数触顶，保护你不陷入无限循环。这时应告诉用户「任务未完成，已达步数上限」。

条件 C (L8 加入)

工具执行失败且无法恢复

工具抛异常后，如果模型自己无法换方案，loop 应该优雅退出而不是崩掉。

5. 不止「能跑」：轨迹（trajectory）是 Agent 的日志系统

单轮 demo 你只需要看 console.log(output_text)。Agent 有多步，你必须要能回溯每一步发生了什么。 行业里管这个叫 trajectory（轨迹）。

最小可行轨迹 = 每步存下：

  • 步数（step index）
  • 模型说了什么（output 中的 text/message）
  • 模型调了哪些工具 + 参数（function_call items）
  • 工具返回了什么（function_call_output items）

本课只要求 console.log 打出轨迹。后续 L6 会做结构化日志。
