流式调用与会话衔接：连接单步和循环的胶水

L3 你会了"调一次模型、执行工具、再调一次"。L5 你会了 while 循环。但中间少了一环： 模型输出是逐 token 流回来的，工具调用也在流里——你得知道怎么拆流、怎么用 previous_response_id 把多轮串成对话，以及除了 function tool 还有哪些工具类型。

约 12–18 分钟 前置：L0–L3（已掌握） 术语表 Agent Loop 速查

1. 流式调用解决什么问题

非流式调用（stream: false）下，你必须等模型完全生成完才能拿到 output。这意味着：

  • 用户盯着空白画面等几秒 → 体验差
  • 你不知道模型要调哪个工具，直到 response 全返回来 → 不能边收边决定
  • 每次调用的 response.id 是 stream: false 也会返回的 —— 关键是流式中你必须从事件流里拿到它

流式调用（stream: true）把模型输出拆成事件序列。你库里的 getWeatherFunctionCalling 就是标准范例——我们逐帧看它做了什么。

四个关键事件

const stream = await client.responses.create({
  model: 'gpt-5.4-mini', input, tools,
  stream: true,   // ← 关键开关
  store: true,    // ← 流式下 store 才能拿到 previous_response_id
});

for await (const event of stream) {
  // ① response.created       → 拿到 response.id，存到变量里
  // ② response.output_item.done → function_call 的完整信息（name + arguments + call_id）
  // ③ response.content_part.done / output_text.delta → 文本输出（流式输出时可逐字显示）
  // ④ response.completed      → 流结束，response.output_text 可用
}
事件携带什么你用它做什么
response.created event.response.id 记下 response_id，后续用 previous_response_id 续接
response.output_item.done event.item（类型为 function_call） 拿到 name + arguments + call_id，执行工具
response.output_text.delta event.delta 逐字显示输出（可选，后续可加）
response.completed event.response（完整对象） 确认响应结束，取 output_text
注意：stream: true 时必须同时 store: true， 否则 previous_response_id 无法用于后续请求——流式响应默认不存储。

2. previous_response_id：多轮会话的钩子

你库里的 getWeatherFunctionCalling 分了两步：

  1. 第一次流式调用：模型输出 function_call，你执行工具，收集 function_call_output
  2. 第二次流式调用：带上 previous_response_id: responseId，模型根据工具结果生成最终答案
手动拼接 input 
// L3 方式：自己 push 历史
input.push(functionCall);
input.push(functionCallOutput);
await client.responses.create({ input });
previous_response_id 
// previous_response_id 方式
await client.responses.create({
  input: functionCallOutputs,
  previous_response_id: responseId,
});
// 平台替你维护对话历史

两者的区别：

手动拼接 inputprevious_response_id
控制力 你完全控制上下文 平台接管，你只管增量
心智负担 自己维护历史数组 只传本轮新增内容
适用场景 需要裁剪/修改历史时 简单串联多轮时
Agent Loop 中 ✅ 常见：每步 push output + tool result ⚠️ 不推荐循环内用（无法插入/查看历史）
一句话决策：Agent Loop 内部用手动拼接 input（透明度最高）； 简单多轮对话/原型阶段用 previous_response_id（代码最少）。

3. 不止 function tool：内置工具一览

你目前只用了 type: 'function'。OpenAI 还提供了内置工具，不需要你写执行逻辑：

工具类型type 值用途你需要做什么
函数工具 'function' 你定义 + 你执行的自定义工具 写 schema + 写执行逻辑
网页搜索 'web_search_preview' 让模型实时搜索网络 只定义工具，不写执行逻辑
代码执行 'code_interpreter' 沙箱里跑 Python 只定义工具，不写执行逻辑
文件搜索 'file_search' 搜索上传的文件 先上传文件到 vector store
MCP 'mcp' 连接外部 MCP 服务器 配置 MCP 连接信息 
// 内置工具示例（不需 executeTool）
{
  type: 'web_search_preview',
  user_location: { type: 'approximate', city: '深圳' },
  search_context_size: 'medium',
}

内置工具的关键区别：模型调用后，平台自动执行并返回结果——你不需要拦截 function_call 然后自己跑。但这也意味着你不能对执行结果做校验或转换。 对于生产力 Agent，核心业务工具还是用 function 类型，辅助信息获取可用内置工具。

4. 流式 + Agent Loop：该不该合并？

你的 src/Agent/loop.ts 目前用非流式（stream: false）。 如果要改成流式，核心循环会变成这样： 

while (steps < maxSteps) {
  const stream = client.responses.create({ stream: true, /* ... */ });
  let responseId = '';
  const toolCalls: FunctionCallItem[] = [];
  for await (const event of stream) {
    if (event.type === 'response.created') responseId = event.response.id;
    if (event.type === 'response.output_item.done' && event.item.type === 'function_call')
      toolCalls.push(event.item);
    if (event.type === 'response.output_text.delta')
      process.stdout.write(event.delta);  // 实时输出
  }
  if (toolCalls.length === 0) break;
  // 执行工具，push 结果...
}

建议：非流式 Agent Loop 先跑稳，再加流式。流式增加的复杂度（事件分发、多 tool 并行等） 不是 L5 的核心问题。L4 的掌握标准是：能写一个流式 tool calling demo， 并解释每个事件的作用，不必着急把 Loop 全改成流式。
