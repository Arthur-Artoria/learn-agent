工具设计：模型看不懂的 tool，等于没写

Agent Loop 跑通了，但当你把 mock 工具换成真实工具时，一个新的问题浮出水面： 模型怎么用你的工具，取决于你怎么"介绍"这些工具。工具描述就是模型的使用说明书。

约 10–15 分钟 前置：L0–L5（已掌握） 术语表 工具设计速查

1. 工具不是 API，是给 AI 看的"合同"

这是本课最核心的认知转变：

传统 API

确定性系统 ↔ 确定性系统
调用方知道精确的入参格式
错误码是给程序员读的

Agent Tool

非确定性 LLM ↔ 确定性代码
模型从自然语言中推断何时调用
错误信息要能引导模型修正

Anthropic 的原话： "Tools are a new kind of software — a contract between deterministic systems and non-deterministic agents."
— Writing effective tools for agents

2. 三个支柱：name · description · parameters

一个工具定义由三部分组成。每一部分的打磨都会直接影响模型的调用准确率：

支柱好例子差例子
name get_weather、add_todo tool_1、handleStuff
description "获取指定城市的当前天气，返回温度、湿度和天气状况" "天气工具"
parameters {city: string, units?: "celsius"|"fahrenheit"} {data: object}

name 规则

  • 用 动词_名词 格式，小写 + 下划线
  • 名称本身就是最低成本的描述——模型看到 search_contacts 比 list_contacts 更准确知道要做什么
  • 如果工具多了，用前缀命名空间：todo_add、todo_list、file_read

description 是 80% 的功夫

Anthropic 的建议："像给团队新同事解释这个工具一样写描述。" 好的 description 应该包含：

  1. 做什么——一句话说清功能
  2. 何时用——什么场景下该调这个工具而不是别的
  3. 返回什么——输出格式的简要说明
  4. 边界——什么情况不该用（比如"不能修改已有事件"）
// 好的 description
description: "添加一条新的待办事项到任务列表。返回创建成功的 todo 对象，
包含自动生成的 id 和时间戳。仅用于创建新任务，不能用于修改或删除已有任务。"

parameters 最关键的两个开关

parameters: {
  type: 'object',
  properties: { /* ... */ },
  required: ['title'],          // 必填字段列表
  additionalProperties: false,  // 禁止模型编造参数
}

additionalProperties: false 是防止模型幻觉的重要护栏——没有它，模型可能凭空添加 priority_level 之类的字段。

3. 工具出错时：别崩，教会模型怎么做

你的 executeTool 目前是 switch/case + 直接返回字符串，一切正常。真实工具会失败——文件不存在、API 超时、参数格式错。

处理原则：

// ❌ 绝对不要这样——模型不知道发生了什么
throw new Error("ENOENT: no such file")

// ✅ 返回结构化的错误文本，告诉模型怎么修正
return "错误：文件 'tasks.json' 不存在。
建议：先用 create_file 工具创建 tasks.json，再重试。"

Anthropic 把这种思路叫 Poka-yoke（防错设计）——让正确做法比错误做法更容易。 参数名叫 user_id 比叫 user 更不容易传错类型。

4. 工具注册表：让 Agent Loop 不再认识具体工具

你现在 loop.ts 里的 executeTool 是从 FunctionCalling.ts 导入的 switch/case。 每加一个新工具就要改这个函数——这会让它快速膨胀。

工具注册表模式：

// src/tools/registry.ts
type ToolHandler = (args: Record<string, unknown>) => Promise<string>;

const registry = new Map<string, { schema: Tool; handler: ToolHandler }>();

export function registerTool(name: string, schema: Tool, handler: ToolHandler) {
  registry.set(name, { schema, handler });
}

export function getToolSchemas(): Tool[] {
  return [...registry.values()].map(r => r.schema);
}

export async function executeTool(call: ResponseFunctionToolCall): Promise<string> {
  const tool = registry.get(call.name);
  if (!tool) return `错误：未知工具 "${call.name}"`;
  try {
    return await tool.handler(JSON.parse(call.arguments));
  } catch (e) {
    return `工具 "${call.name}" 执行失败：${e instanceof Error ? e.message : String(e)}`;
  }
}

这样 Agent Loop 只依赖 executeTool 和 getToolSchemas()，不知道任何具体工具的存在。
