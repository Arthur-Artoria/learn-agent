# 0009 — 生产力 Agent MVP

## 学到了什么
- **MVP 的定位**：不是"所有功能都做完"，是三条端到端用户故事能跑通 + 陌生人按 README 十分钟能跑起来
- **CLI REPL 模式**：用 `node:readline` 实现 load session → runAgent → save session 的交互循环，替代硬编码顺序执行
- **三个用户故事**：快速记录（批量添加）、上下文回顾（多轮追问标记完成）、规划清理（全量分析去重排序）——覆盖了 loop / session / 工具编排的核心协作
- **README 六小节**：一句话是什么 / 前置条件 / 安装 / 运行 / 三条演示 / 跑评测——本质是 onboarding 路径不是文档

## 为什么重要
这是 Mission 的直接交付物。从 L0 到 L8 的所有代码最终汇聚成一个可演示的产品。面试官看 repo 时，README 和终端录屏决定了第一印象；三个用户故事决定了你的 Agent 是"玩具"还是"工具"。

## 关键决策
- CLI 入口用 `node:readline` 而非 Web UI——最轻量的交互方式，不引入额外依赖
- MVP 不追求完整命令系统（/clear /undo 等），聚焦核心对话闭环
- 用户故事选择"记录→回顾→规划"三条路线，覆盖 CRUD 全生命周期

## 待扩展
- 支持命令前缀（/help /clear /export）提升使用体验
- 添加简单的 TUI 颜色输出（chalk 或不依赖）
- 用户故事扩展：日程提醒、定期任务
